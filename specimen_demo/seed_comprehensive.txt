# ============================================================================
# GRUG COMPREHENSIVE SPECIMEN SEED SCRIPT
# ============================================================================
# Pipe this file into the CLI (the build driver strips comments/blanks):
#   julia --project=. -e 'using GrugBot420; GrugBot420.run_cli()' \
#     < specimen_demo/seed_comprehensive.txt
#
# Seeds four orthogonal subject lobes (physics, cooking, music, ethics)
# with lobe-attached nodes, AIML tribes, orchestration rules, verbs,
# synonyms, thesaurus inhibitions, relational node attachments, and
# pinned memory, then saves the whole cave to
# grugbot420_comprehensive.specimen.gz.
#
# ACTION VOCABULARY CONSTRAINT:
#   All action tokens in action_packet and /aimlAdd must come from the
#   hardcoded COMMANDS registry in Main.jl. Valid families are:
#     reason-family  : reason, analyze, ponder, calculate
#     greet-family   : greet, welcome, smile, laugh
#     survival-family: flee, hide, fight
#     explain-family : explain, clarify, describe, define, elaborate
#     empathy-family : comfort, support, validate, acknowledge, reassure
#     warning-family : alert, warn, caution, notify, flag
#   Unknown verbs crash the cast_votes sub-process with "unknown action"
#   at runtime, so we stay strictly inside the registered vocabulary.
#
# NODE CONTEXT CONSTRAINT:
#   generate_aiml_payload() reads node.json_data["system_prompt"] and
#   throws FATAL if the key is missing. Every /lobeGrow payload below
#   embeds an explicit system_prompt tailored to the node's subject.
#
# LOBE-ATTACHMENT CONSTRAINT:
#   /grow mints a node into NODE_MAP but does NOT bind it to any lobe,
#   leaving NODE_TO_LOBE_IDX empty and forcing lobe cascade/context
#   extraction to return "[Unassigned nodes - no lobe context]". We use
#   /lobeGrow <lobe> {...} instead so every node is registered to its
#   owning lobe at creation time.
#
# JSON PACKET SHAPE FOR /lobeGrow:
#   Unlike /grow, which nests arbitrary fields under "json_data" inside a
#   "nodes" array, /lobeGrow expects the flat form:
#     {"pattern":..., "action_packet":..., "data":{...}, "drop_table":[...]}
#   The "data" sub-dict becomes the node's json_data. So system_prompt
#   lives under data.system_prompt here.
#
# ID ARITHMETIC:
#   Cave boots with 3 seed nodes (node_0..node_2). Each /lobeGrow mints
#   ONE new node, so IDs are:
#     physics : node_3  node_4  node_5  node_6  node_7
#     cooking : node_8  node_9  node_10 node_11 node_12
#     music   : node_13 node_14 node_15 node_16 node_17
#     ethics  : node_18 node_19 node_20 node_21 node_22
#   /nodeAttach commands reference these explicit IDs.
# ============================================================================

# ----------------------------------------------------------------------------
# STOCHASTIC ORCHESTRATION RULES
# Magic word tags get substituted by the vote orchestrator when a rule
# fires (coinflip against fire_probability).
# ----------------------------------------------------------------------------
# GRUG v7.15: Orchestration rules are TONE / VOICE DIRECTIVES, not
# variable-echo templates. The scaffold is a conversational reply —
# rules shape how it is spoken, they do not name internal IDs, confidences,
# or vote states. All placeholders that DO appear are conversational
# flavor, not statistics (e.g. {MISSION} is the user's question).
/addRule Answer "{MISSION}" in one tight paragraph — no lists, no hedging ladders. [prob=1.0]
/addRule Ground the reply in a concrete example before stating any general principle. [prob=0.8]
/addRule Stay inside the {LOBE_CONTEXT} frame — do not wander into unrelated domains. [prob=0.85]
/addRule If the claim leans on a cause-effect chain, state the cause first, then the effect. [prob=0.7]
/addRule When the topic touches harm, consent, or fairness, include at least one mitigating consideration. [prob=1.0]
/addRule Speak with the persona in the system_prompt — do not break voice mid-reply. [prob=0.9]
/addRule If confidence is shaky, hedge once plainly ("this is roughly true when...") — never stack caveats. [prob=0.6]
/addRule Close with a short, actionable takeaway the reader can use. [prob=0.5]
