# v7.15.2 Wiring Pass — End-User Hotwire + QoL Fixes

**Date:** 2025-05-11
**Branch:** `v7.15-updates`
**Spec:** "go through the entire project. hot wire any changes so the end user can easily use them. but also just any quality of life small fixes as you go. test it all comprehensively error handling first no silent failures keep comments consistent etc"

## Summary

v7.15 introduced seven new modules (`LobeOrchestrator`, `GroupRegistry`,
`CrystalizeTag`, `ChatterVoteSwap`, `DynamicActionTonePredictor`,
`PhagyGroupOrganizer`, plus RelationalJitter v7.15 extensions). They all
exported clean APIs, but **none of them were wired into the live engine**.
End users had to call them programmatically by reaching into the package
namespace. This pass hotwires everything the end user needs and adds CLI
surface area for every new capability.

## Gaps Closed

| # | Wiring Gap | Fix |
|---|------------|-----|
| 1 | Phagy 7th automaton existed but wasn't in the roll | Pluggable hook in `PhagyMode.register_group_organizer!`; `run_phagy!` rolls 1..7 when wired, 1..6 otherwise. No circular include. |
| 2 | `grave_node_in_group!` required caller to know group ids | Added `grave_node_everywhere!(node_id)` — single-call multi-group grave sync via `node_to_groups` reverse index. |
| 3 | `engine.mark_node_grave!` didn't tell GroupRegistry | Wired to call `grave_node_everywhere!` on grave; resilient to standalone-include paths via `isdefined` guard. |
| 4 | `engine.penalize_strength!` strength-zero path didn't tell GroupRegistry | Same fix as #3; only syncs when the penalty actually tipped the grave bit. |
| 5 | No CLI verbs for any v7.15 feature | 13 new verbs: `/groupStatus`, `/groupRegister`, `/groupGrave`, `/groupWindow`, `/crystalize`, `/uncrystalize`, `/crystalizeList`, `/crystalizeAuto`, `/chatterSwap`, `/phagy`, `/groupOrganize`, `/groupSnapshot`, `/groupRestore`. |
| 6 | `HELP_MSG` missing all v7.15 verbs | New "v7.15 --- GROUPS, CRYSTALIZE, CHATTER-SWAP, PHAGY" section. |
| 7 | Main.jl standalone mode crashed on new verbs (`UndefVarError: CrystalizeTag`) | Added guarded `isdefined` includes for every v7.15 module. `PhagyMode.register_group_organizer!` auto-wired in standalone mode too. |

## Design Invariants Preserved

- **No silent failures.** Every new handler either throws a typed error (with
  context breadcrumb) or prints a user-facing `!!!` line. `register_group_organizer!`
  explicitly rejects `nothing` and non-callables with `PhagyError` rather than
  letting `MethodError` bubble up.
- **No circular deps.** PhagyMode (loaded upstream) cannot `using .PhagyGroupOrganizer`
  (loaded downstream). Fixed via `Ref{Union{Nothing,Function}}` hook installed
  post-load by `GrugBot420.jl`.
- **Standalone include compatibility.** `engine.jl` used to be `include`d directly
  by `test/test_smoke.jl` and similar files. The new GroupRegistry sync is gated
  on `isdefined(@__MODULE__, :GroupRegistry)` so standalone-loaded engine still
  works. `Main.jl` standalone mode now includes every v7.15 module with the
  same `isdefined` guard pattern the existing modules already use.
- **No numerical behavior changes** to any existing command. Every v7.15 feature
  is opt-in through explicit CLI verbs. The existing `/mission`, `/grow`,
  `/wrong`, `/right`, etc. continue to work exactly as before — with the one
  additive side-effect that `mark_node_grave!` now also pings `GroupRegistry`
  (a no-op if the node was never group-registered, which is the baseline case).
